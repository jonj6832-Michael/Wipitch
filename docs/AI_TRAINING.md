# 手動修音訓練資料

使用專案的「啟動WiPitch.command」或 `npm run dev`。本機儲存服務隨 Vite 啟動；靜態網站或 `file://` 不支援此功能。MP3 編碼使用本機 ffmpeg-static，不傳送到 AI 或雲端。

## 自動記錄條件

修改選取／畫筆起訖範圍 **超過 5 秒不記錄**，剛好 5 秒仍保存。前後各 3 秒上下文不計入限制，合格片段最長可達 11 秒。前端略過資料擷取，儲存端也拒絕超限記錄；修音功能照常執行。此規則適用新記錄，不刪除既有資料。

- 手動音高拖曳、音高畫筆、移調滑桿、抖動／壓平滑桿、音高／全部歸零。
- 一般手動修音與 AI 後人工調整在音訊算繪成功後，先將前後 MP3、小型圖檔與對應資料寫入專案下的 `AI訓練暫存/`；按下整首歌曲「匯出 WAV」才搬入正式目錄。取消 AI 修正是明確的負例，按「完成工作」時直接寫入 `AI訓練/AI修正調整/取消修正/`。
- AI 自動修音、播放、只改 Key、只改選取、單獨音量／Formant、時間伸縮、復原與重做不新增訓練樣本。
- 每次提交（放開滑鼠／滑桿）一筆；連續滑桿操作即使共用一步復原，也各自記錄。
- 以修改選取起點前 3 秒至修改終點後 3 秒為完整記錄範圍；畫筆使用筆畫最早／最晚時間。超過歌曲邊界則截到歌曲頭尾。前後 MP3、圖片與逐點資料均涵蓋相同完整範圍。
- 音訊是修改當下的工作算繪版本，尚未包含後續背景精算；不是原始檔案未編輯的聲音。前一筆已修改的結果會成為下一筆的「修正前」。

## 目錄與檔案對應

```text
AI訓練/
  <音檔載入識別碼>/
    <操作識別碼>/
      before.mp3
      after.mp3
      pitch.png
      音高行對應.csv
      record.json
      對應表.csv
```

音檔以載入識別碼分類，原始檔名、大小、最後修改時間記在對應表。同一檔案重新載入會建立新的識別碼，避免混淆不同操作工作階段。每筆完整寫入後才出現正式操作目錄；失敗會清理未完成目錄。訓練資料目錄已加入 Git 忽略名單。

| 欄位／檔案 | 訓練用途 |
|---|---|
| before.mp3 / after.mp3 | 同一輸出時間範圍的修改前／後聲音，192 kbps MP3 |
| pitch.png | 小區域疊圖：灰色修正前，藍／紅／綠修正後；最多 480×256 像素 |
| 音高行對應.csv | 每條橫線的 y 像素、MIDI、音名及頻率 Hz |
| key | 當下 Key 完整設定；全部音時為 null |
| keySelection | 手動修改完成時選單的 value、畫面顯示文字 label、擷取時間 capturedAt；「全部音」也明確記錄。匯出時不重新讀取 Key |
| selection | 當下完整編輯選取範圍，輸出秒數 |
| editRange | 本次選取／筆畫範圍，輸出秒數 |
| detectionRange | 當下獨立檢測列範圍；不控制手動編輯 |
| clip | 真正保存的起點、終點、長度，涵蓋修改區域及前後各 3 秒 |
| renderRange | 引擎本次重算範圍，可能包含銜接邊界 |
| operation / parameters / pen | 操作名稱、移調／抖動等控制參數及畫筆設定 |
| pitchSlopeLimit / ramp / formantFollow | 斜率限制、過渡長度、音色跟隨設定 |
| anchors | 時間伸縮錨點，將輸出時間對應原始時間 |
| beforePoints / afterPoints | 每 2ms 的輸出時間、來源時間、編輯後絕對 MIDI 音高、偏移量；未發聲的 MIDI 為 null |
| image | 圖片尺寸與共同的 MIDI 音高上下限 |
| sampleRate | 工作音訊取樣率；不是保證原始檔案取樣率 |
| asset / id / createdAt | 音檔資訊、操作識別碼、儲存時間 |
| files | 前後音訊與圖片的明確檔名對應 |
| approval | 固定 unreviewed；代表操作紀錄，尚未確認為滿意結果 |

`record.json` 是完整機器可讀資料；`對應表.csv` 提供該筆操作與檔案的表格對照。數值曲線存於 JSON，避免龐大曲線塞入 CSV。

圖像保留完整記錄時間範圍，不再裁掉修改前後的上下文；仍使用小型 PNG（最多 480×256 像素），將整段時間縮放至圖片寬度。縱軸涵蓋前後音高並各留一個半音。完整精細音高數值保存在 JSON，不依賴縮圖像素精度。image 欄位與音高行對應.csv 提供時間、像素及音高對應。

灰色代表本次修改前；修改後距最近調內音 ≥+25 cents 為紅色、≤−25 cents 為綠色，其餘藍色。重合處彩色線覆蓋灰線。全部音模式修改後使用藍色。若記錄範圍內沒有可見修改點，保留該片段並標記 hasVisibleChange=false，供訓練排除。新版 schemaVersion=3 僅保存一張 pitch.png；既有資料不刪除或補造缺少的前後聲音。

## 限制與訓練使用

MP3 為有損預覽格式；來源高取樣率可能被編碼器轉換為 MP3 支援的取樣率，不能拿來驗證逐取樣點完全相同。原始精確音高曲線另存於 JSON。

復原不會刪除既有手動樣本，目前也不會自動標註該手動樣本被否定；新樣本預設為 unreviewed。資料庫管理中標為 excluded 的資料不會加入內建 AI。一般手動資料與 unreviewed/approved 資料皆可作正例；使用者取消的 AI 修正作負例，AI 後再次人工調整作較高權重正例。

每次頁面啟動時會檢查正式資料的檔案指紋。資料有變動時，重新建立小型內建 AI 模型並原子寫入 `AI訓練/模型/內建AI.json`；沒有變動時直接使用既有模型。更新完成前「內建 AI 模式」反白。傳統固定規則與外部 AI 不依賴這個模型。

頁面底部顯示保存結果。匯出 WAV 時，一般手動修音從 `AI訓練暫存/<音檔ID>/<操作ID>/` 搬入 `AI訓練/<音檔ID>/<操作ID>/`，AI 後人工調整搬入 `AI訓練/AI修正調整/人工調整/<音檔ID>/<操作ID>/`。取消 AI 修正已在取消標示時正式保存，不需要等待匯出。同一檔案系統以目錄 rename 搬移，不重編碼 MP3。成功搬移的暫存記錄立即移除，重複匯出不新增樣本；若部分搬移失敗，其餘待存記錄仍留在暫存區，可再次匯出重試。WAV 下載啟動不代表瀏覽器已完成存檔。

**每次開啟新音檔，先清空整個 `AI訓練暫存/` 目錄內容**，包含上一首歌尚未匯出的資料與未完成的暫存目錄，不再詢問是否保留。正式 `AI訓練/` 內容不受影響。新檔解碼失敗也不還原已清空的暫存。暫存清除失敗時不繼續載入，顯示錯誤。

暫存檔實際位於磁碟，不依赖瀏覽器記憶體；但目前沒有跨重啟續作介面，重新開啟音檔仍會清空暫存。多個頁面共用同一暫存目錄，開啟新檔會使舊頁面的記錄工作階段失效，避免旧資料重新混入。圖片、Key 與音高資料在修音當下固定，不會改用匯出時最後一次設定。暫存目錄與正式目錄均不納入 Git。

## 驗證

`spike/training-test.mjs` 檢查：音高資料的範圍與未發聲處理、本機來源限制、請求 token、實際 MP3 編碼、取消 AI 修正立即正式保存、人工調整暫存與匯出搬移、搬移失敗重試、重複匯出、新檔只清除暫存而保留正式負例、舊工作階段拒絕及素材路徑驗證。已加入 `npm run verify:core`。

仍需以實際手動修音操作驗收畫面、聆聽前後 MP3；自動測試未涵蓋真實瀏覽器手勢與聽感。


## 訓練資料庫管理

「存檔／讀檔」後的「訓練資料庫管理」按鈕開啟管理視窗，只列出正式 `AI訓練/` 的記錄，不列出暫存資料。可搜尋音檔名、Key、操作，選取後檢視：

- 修改前與修改後 MP3，各自有播放器；開始播放其中一個時暫停另一個。
- 同筆音高疊圖、音訊範圍與圖片裁切範圍，以及每行音高對應。
- 當時 Key 顯示文字、操作時間、完整選取與逐點音高 JSON。
- 檔案缺漏提示；讀取異常的記錄保留在清單中供檢查。

MP3 是聲音比對依據，圖片是曲線比對依據；管理視窗依記錄識別碼及時間串聯，不會重新偵測 MP3 或自動宣稱聲音音高與曲線完全一致。壓縮聲音仍須實際聆聽判斷。

可將每笔記錄標記「尚未審核／認可作為訓練參考／排除訓練」及加入經驗備註，寫入該筆資料夾的 `review.json`。原始 `record.json` 保留操作當時資料；後續訓練篩選應讀取 `review.json`，沒有此檔時以未審核處理。本介面不刪除錄音。

管理端自動測試涵蓋清單、音訊與圖像讀取、備註保存、缺檔提示及路徑限制；真實瀏覽器播放與聆聽尚需人工驗收。

單筆請求目前限制 512 MiB；超過會明確報錯，不會將資料偷偷截短成 3 秒。較長的修改範圍會增加暫存與編碼成本。
